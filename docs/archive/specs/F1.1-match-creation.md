# Spec: F1.1 — Match Creation

## Origin
- User Story / Feature: F1.1 — Match Creation
- Layer: 1 (Match Core)

## Summary
Enable an authenticated Organizer to create a recurring or one-off volleyball match with location, confirmation window, and slot configuration so that players can later confirm attendance.

## Primary module
`Quadra.Modules.Matches`

## Dependent modules (read-only via interface)
- `Quadra.Modules.Auth` — the JWT middleware (FA.1) populates `HttpContext.User` with the caller's `UserId` (from the `sub` claim). The Matches module reads `UserId` from the claim; it does not query the `users` table directly.

## REST endpoints

### `POST /api/v1/matches`
- **Auth**: JWT required (`[Authorize]`)
- **Request**:
  ```csharp
  public record CreateMatchRequest(
      string Name,
      string? Description,
      string Address,
      double Latitude,
      double Longitude,
      DateTimeOffset DateTime,
      int MaxPlayers,
      int RegularSlots,
      decimal? Price,
      string Type,               // "Recurring" | "OneOff"
      string? Frequency,         // "Weekly" | "Biweekly" | "Monthly" — required when Type == "Recurring"
      int? DayOfWeek,            // 1–7 (ISO); required when Type == "Recurring"
      DateTimeOffset WindowOpensAt,
      DateTimeOffset WindowClosesAt);
  ```
- **Response 201 Created**: `MatchResponse` (see Contracts section) + `Location: /api/v1/matches/{id}` header
- **Errors**:
  - `400` — validation failure
  - `401` — missing or invalid JWT
- **Behavior**:
  1. Extract `OrganizerId` from `User.FindFirst(ClaimTypes.NameIdentifier)?.Value` (the `sub` claim). If parse fails → `401`.
  2. Run `CreateMatchRequestValidator`; return `400 ValidationProblem` on failure.
  3. Normalize `Type`, `Frequency` to canonical casing.
  4. Construct a `Match` entity via `Match.Create(...)` factory. Initial `status = Draft`.
  5. Persist via `IMatchRepository.AddAsync(match, cancellationToken)`.
  6. Publish `MatchCreated` event to SQS via `IEventPublisher` after commit.
  7. Map entity → `MatchResponse` (manual mapping).
  8. Return `201 Created`.

---

### `GET /api/v1/matches/{id}`
- **Auth**: JWT required (`[Authorize]`)
- **Response 200 OK**: `MatchResponse`
- **Errors**:
  - `401` — missing or invalid JWT
  - `404` — match not found
- **Behavior**:
  1. Call `IMatchRepository.FindByIdAsync(id, cancellationToken)`.
  2. If null → `404 ProblemDetails`.
  3. Map entity → `MatchResponse` → `200 OK`.

---

### `GET /api/v1/matches?organizerId={guid}&status={string}&page={int}&pageSize={int}`
- **Auth**: JWT required (`[Authorize]`)
- **Request** (query parameters):
  ```csharp
  public record ListMatchesQuery(
      Guid? OrganizerId,
      string? Status,
      int Page,
      int PageSize);
  ```
- **Response 200 OK**:
  ```csharp
  public record PagedMatchesResponse(
      IReadOnlyList<MatchResponse> Items,
      int Page,
      int PageSize,
      int TotalCount);
  ```
- **Errors**:
  - `400` — invalid query params
  - `401` — missing or invalid JWT
- **Validation** (`ListMatchesQueryValidator`):
  - `Page`: default 1; must be `>= 1`
  - `PageSize`: default 20; range `[1, 100]`
  - `Status`: when provided, must be one of `Draft | Open | Closed | InProgress | Ended | Cancelled`
- **Behavior**: Build EF query with optional filters on `organizer_id` and `status`; order by `date_time DESC`; apply skip/take; return paginated result.

---

### `DELETE /api/v1/matches/{id}`
- **Auth**: JWT required (`[Authorize]`)
- **Response 204 No Content**
- **Errors**:
  - `401` — missing or invalid JWT
  - `403` — caller is not the match organizer
  - `404` — match not found
  - `409` — match is `InProgress` or `Ended` (terminal — cannot cancel)
- **Behavior**:
  1. Load match; return `404` if not found.
  2. Verify `OrganizerId == callerUserId`; return `403` if mismatch.
  3. If `status` is `InProgress` or `Ended` → `409`.
  4. Call `match.Cancel()` (sets `Status = Cancelled`, bumps `updated_at`).
  5. Persist via `IMatchRepository.UpdateAsync(match, cancellationToken)`.
  6. Publish `MatchStatusChanged` to SQS after commit.
  7. Return `204 No Content`.

## Validation rules (`CreateMatchRequestValidator`)

| Field | Rule |
|---|---|
| `Name` | Required; max 120 chars; not whitespace-only |
| `Description` | Optional; max 2000 chars when provided |
| `Address` | Required; max 300 chars; not whitespace-only |
| `Latitude` | Range `[-90, 90]` |
| `Longitude` | Range `[-180, 180]` |
| `DateTime` | Must be in the future (`TimeProvider.GetUtcNow()`) |
| `MaxPlayers` | Range `[2, 100]` |
| `RegularSlots` | `>= 0` and `<= MaxPlayers` |
| `Price` | When provided: `>= 0` and `<= 9999.99` |
| `Type` | Required; must be `Recurring` or `OneOff` (case-insensitive) |
| When `Type == "Recurring"` | `Frequency` required (`Weekly\|Biweekly\|Monthly`); `DayOfWeek` required (range `[1, 7]`) |
| When `Type == "OneOff"` | `Frequency` must be null; `DayOfWeek` must be null |
| `WindowOpensAt` | Must be in the future; must be before `WindowClosesAt` |
| `WindowClosesAt` | Must be before `DateTime` |

## Acceptance criteria

- [ ] AC-1: `POST /api/v1/matches` with valid `OneOff` payload returns `201 Created` with a `MatchResponse` body and `Location` header; `status = Draft`.
- [ ] AC-2: `POST /api/v1/matches` with valid `Recurring` payload (including `Frequency` and `DayOfWeek`) returns `201 Created`.
- [ ] AC-3: `POST /api/v1/matches` without auth returns `401`.
- [ ] AC-4: `POST /api/v1/matches` with `MaxPlayers = 1` (below minimum) returns `400` with validation errors.
- [ ] AC-5: `POST /api/v1/matches` with `RegularSlots > MaxPlayers` returns `400`.
- [ ] AC-6: `POST /api/v1/matches` with `Type = Recurring` but missing `Frequency` returns `400`.
- [ ] AC-7: `POST /api/v1/matches` with `WindowClosesAt` after `DateTime` returns `400`.
- [ ] AC-8: `POST /api/v1/matches` publishes a `MatchCreated` SQS event after commit (verified via mock `IEventPublisher`).
- [ ] AC-9: `GET /api/v1/matches/{id}` returns `200` with the correct `MatchResponse` for an existing match.
- [ ] AC-10: `GET /api/v1/matches/{id}` returns `404` for a non-existent `id`.
- [ ] AC-11: `GET /api/v1/matches?page=1&pageSize=10` returns paginated results with `TotalCount`.
- [ ] AC-12: `DELETE /api/v1/matches/{id}` by the organizer on a `Draft` match returns `204` and sets `status = Cancelled`.
- [ ] AC-13: `DELETE /api/v1/matches/{id}` by a different user returns `403`.
- [ ] AC-14: `DELETE /api/v1/matches/{id}` when `status = InProgress` returns `409`.
- [ ] AC-15: `DELETE /api/v1/matches/{id}` publishes `MatchStatusChanged` event after successful cancellation.

## Out of scope (explicit)

- Presence confirmation, waiting list, DropIn slot release — F1.2
- Team drafting, live scoreboard — F1.3 / F1.4
- MVP voting — F1.5
- Match summary endpoint — F1.6
- Geographic proximity search — F1.7 (`Geo` module)
- Editing a match after creation (beyond cancellation) — not in MVP SCOPE
- Payment / cost splitting between players — explicitly OUT per SCOPE
- External calendar integration (Google Calendar, iCal) — explicitly OUT per SCOPE
- Push notifications triggered by match creation — `Notifications` module reacts to `MatchCreated` event; this spec only publishes the event
- Role-based authorization beyond "authenticated user" — no JWT role claim in MVP
- Recurring match instance generation — deferred
- `PATCH /api/v1/matches/{id}` — not in SCOPE

## Implementation notes

- **`location` mapping**: use `NetTopologySuite.Geometries.Point`; configure `HasColumnType("geography (point, 4326)")` in `MatchConfiguration`; add `UseNetTopologySuite()` in `AddMatchesModule`.
- **`drop_in_slots` computed column**: EF maps via `HasComputedColumnSql("max_players - regular_slots", stored: true)`. Property is getter-only on the entity.
- **`day_of_week` encoding**: ISO 8601 (1=Monday, 7=Sunday). C# `DayOfWeek` uses 0=Sunday — conversion required in `Match.Create`.
- **Status machine**: only `Draft → Cancelled` is in scope here. `Cancel()` throws `InvalidMatchStatusTransitionException` if `status` is `InProgress` or `Ended`.
- **`OrganizerId` from claims**: `User.FindFirst(ClaimTypes.NameIdentifier)?.Value` mapped by `CognitoClaimsTransformer` in Auth module.
- **Module boundary**: `Matches` never queries `users` table; no EF navigation to `User`.
- **`TimeProvider` injection**: inject into validators and handlers; use `TimeProvider.GetUtcNow()` for all future-date checks.
- **Event after commit**: publish only after `SaveChangesAsync` succeeds.
- **GIST index**: `HasIndex(m => m.Location).HasMethod("gist")` in `MatchConfiguration`.
- **Controller thinness**: actions invoke FluentValidation, call handler, map exceptions to ProblemDetails. No business logic.
- **Configuration fail-fast**: SQS queue URLs bound at startup in `MatchesModuleExtensions`; missing config throws at startup.
- **Serilog**: log `MatchId`, `OrganizerId`, `Type`, `Status` on create; log `MatchId`, `PreviousStatus` on cancel. Never log `price` or `description` at Info+ (potential PII).
- **`MatchesDbContext` isolation**: owns only `matches` table in this spec. Future F1.2 tables added via separate migration.
