# Spec: F1.3 — In-Game: Teams

## Origin
- User Story / Feature from SCOPE: F1.3 — In-Game: Teams
- Layer: 1
- Requested by: Renan Johny Ortega

## Goal
Enable the Organizer to form two balanced teams from confirmed players in a match, either through an automatic level-based draft or through manual player assignment adjustments.

## Primary module
`Quadra.Modules.InGame`

## Dependent modules (read-only via interface)
- `Quadra.Modules.Matches` — to verify match existence and status, and to retrieve the list of confirmed players for a match (via `IConfirmedPlayersReader` interface declared in `Quadra.Shared`, implemented in `Quadra.Modules.Matches`)
- `Quadra.Modules.Profile` — to query player levels for balancing (via `IPlayerLevelReader` interface declared in `Quadra.Shared`; no implementation exists yet — `Quadra.Infrastructure` provides a `NoOpPlayerLevelReader` that returns `Beginner` for every player until F2.1 is delivered)

## Database changes

### New tables

#### `teams`
- `id` `uuid` `PRIMARY KEY DEFAULT gen_random_uuid()`
- `match_id` `uuid` `NOT NULL` — app-layer FK to `matches.id`; no DDL FK (module boundary rule)
- `name` `varchar(32)` `NOT NULL` — e.g. `"Team A"` / `"Team B"`
- `created_at` `timestamptz` `NOT NULL DEFAULT now()`
- `updated_at` `timestamptz` `NOT NULL DEFAULT now()`

**Constraints:**
- `UNIQUE (match_id, name)` — each team name is unique within a match

**Indexes:**
- btree on `match_id`

#### `team_members`
- `id` `uuid` `PRIMARY KEY DEFAULT gen_random_uuid()`
- `team_id` `uuid` `NOT NULL` — app-layer FK to `teams.id`; no DDL FK (module boundary rule)
- `match_id` `uuid` `NOT NULL` — denormalized for efficient per-match queries; app-layer FK to `matches.id`; no DDL FK
- `player_id` `uuid` `NOT NULL` — app-layer FK to `users.id`; no DDL FK
- `created_at` `timestamptz` `NOT NULL DEFAULT now()`

**Constraints:**
- `UNIQUE (match_id, player_id)` — a player can only belong to one team per match

**Indexes:**
- btree on `team_id`
- btree on `match_id`
- btree on `(match_id, player_id)`

### New columns in existing tables
None.

## REST endpoints

### `POST /api/v1/matches/{matchId}/teams/draft`
- **Auth**: JWT required (`[Authorize]`)
- **Request**: no body
- **Response 200 OK**:
  ```csharp
  public record TeamsResponse(
      IReadOnlyList<TeamResponse> Teams);

  public record TeamResponse(
      Guid Id,
      Guid MatchId,
      string Name,
      IReadOnlyList<TeamMemberResponse> Members,
      DateTimeOffset CreatedAt,
      DateTimeOffset UpdatedAt);

  public record TeamMemberResponse(
      Guid Id,
      Guid TeamId,
      Guid PlayerId,
      string PlayerLevel,
      DateTimeOffset CreatedAt);
  ```
- **Possible errors**:
  - `401` — missing or invalid JWT
  - `403` — caller is not the match organizer
  - `404` — match not found
  - `409` — match status is not `Closed`; or match has no confirmed players
- **Behavior**:
  1. Extract `callerId` from `User.FindFirst(ClaimTypes.NameIdentifier)?.Value`; return `401` if parse fails.
  2. Call `IMatchReader.FindMatchSummaryAsync(matchId, cancellationToken)`; return `404` if not found.
  3. Verify `callerId == matchSummary.OrganizerId`; return `403` if mismatch.
  4. If `matchSummary.Status != "Closed"` → `409 ConflictProblem("Teams can only be drafted after the confirmation window closes. Match must be in Closed status.")`.
  5. Call `IConfirmedPlayersReader.GetConfirmedPlayerIdsAsync(matchId, cancellationToken)` to retrieve the list of confirmed player IDs; if the list is empty → `409 ConflictProblem("No confirmed players found for this match.")`.
  6. Call `IPlayerLevelReader.GetPlayerLevelsAsync(playerIds, cancellationToken)` to retrieve a `Dictionary<Guid, string>` of `playerId → level` (level is one of `Beginner | Intermediate | Advanced | Elite`).
  7. Apply the snake-draft balancing algorithm (see Implementation notes).
  8. Delete any existing `team_members` and `teams` rows for `matchId` (idempotent re-draft).
  9. Persist the two new `Team` aggregates with their `TeamMember` children via `ITeamRepository.ReplaceTeamsAsync(matchId, teams, cancellationToken)` inside a single transaction.
  10. Publish `TeamsFormed` event to SQS via `IEventPublisher` after commit.
  11. Map entities → `TeamsResponse` (include `PlayerLevel` from the level dictionary fetched in step 6).
  12. Return `200 OK`.

---

### `GET /api/v1/matches/{matchId}/teams`
- **Auth**: JWT required (`[Authorize]`)
- **Response 200 OK**: `TeamsResponse` (same record as above)
- **Possible errors**:
  - `401` — missing or invalid JWT
  - `404` — match not found; or teams have not yet been drafted for this match
- **Behavior**:
  1. Load match summary via `IMatchReader.FindMatchSummaryAsync(matchId, cancellationToken)`; return `404` if not found.
  2. Load teams via `ITeamRepository.ListByMatchAsync(matchId, cancellationToken)`; if result is empty → `404 ProblemDetails("Teams have not been formed for this match yet.")`.
  3. Retrieve player levels via `IPlayerLevelReader.GetPlayerLevelsAsync(allPlayerIds, cancellationToken)` to populate `PlayerLevel` fields.
  4. Map entities → `TeamsResponse` → `200 OK`.

---

### `PUT /api/v1/matches/{matchId}/teams/{teamId}/members/{playerId}`
- **Auth**: JWT required (`[Authorize]`)
- **Request**: no body
- **Response 200 OK**: `TeamsResponse` (full updated teams state)
- **Possible errors**:
  - `401` — missing or invalid JWT
  - `403` — caller is not the match organizer
  - `404` — match not found; or teams not yet formed; or `teamId` not found for this match; or `playerId` not a member of any team in this match
  - `409` — match status is not `Closed`
- **Behavior**:
  1. Extract `callerId` from JWT; return `401` if parse fails.
  2. Load match summary via `IMatchReader.FindMatchSummaryAsync(matchId, cancellationToken)`; return `404` if not found.
  3. Verify `callerId == matchSummary.OrganizerId`; return `403` if mismatch.
  4. If `matchSummary.Status != "Closed"` → `409 ConflictProblem("Manual team adjustments are only allowed while the match is Closed.")`.
  5. Load all teams for `matchId` via `ITeamRepository.ListByMatchAsync(matchId, cancellationToken)`; if empty → `404 ProblemDetails("Teams have not been formed for this match yet.")`.
  6. Verify `teamId` is one of the loaded teams; return `404` if not found.
  7. Find the `TeamMember` row where `match_id = matchId AND player_id = playerId`; return `404 ProblemDetails("Player is not a member of any team in this match.")` if not found.
  8. If the player is already in the target `teamId` → return `200 OK` with current state (no-op, idempotent).
  9. Move the player: update the `team_id` on the existing `TeamMember` row to `teamId`.
  10. Persist via `ITeamRepository.MovePlayerAsync(memberId, targetTeamId, cancellationToken)`.
  11. Reload and return updated `TeamsResponse` → `200 OK`.

## Acceptance criteria (from SCOPE)
- [ ] Team draft balanced by player level: `POST /api/v1/matches/{matchId}/teams/draft` distributes confirmed players into two teams using the snake-draft algorithm keyed on player level; the absolute difference in total level-score between the two teams must be ≤ 1 level unit for an even number of players.
- [ ] Manual team adjustment by the Organizer: `PUT /api/v1/matches/{matchId}/teams/{teamId}/members/{playerId}` moves the specified player to the specified team and returns the updated full team composition.

## Out of scope (be explicit)
- Balancing by preferred position — explicitly OUT per SCOPE F1.3 ("push to v2")
- History of who played with whom — explicitly OUT per SCOPE F1.3
- Live scoreboard, set-by-set tracking — F1.4
- Match status transition to `InProgress` — F1.4

## Implementation notes

- **Snake-draft balancing algorithm**: (a) Sort confirmed players by level descending, mapping `Elite=3`, `Advanced=2`, `Intermediate=1`, `Beginner=0`. (b) Assign players alternately to Team A and Team B in snake-draft order (player 1 → A, player 2 → B, player 3 → B, player 4 → A, …). This ensures level-score difference is at most 1 unit regardless of player count. (c) For players with the same level, order is arbitrary (stable sort on `PlayerId` for determinism in tests).
- **Idempotent re-draft**: `ReplaceTeamsAsync` deletes all existing `team_members` and `teams` rows for `matchId` and inserts the new ones inside a single database transaction. Calling the draft endpoint a second time always produces a fresh balanced assignment.
- **`IMatchReader` and `IConfirmedPlayersReader`**: both interfaces are declared in `Quadra.Shared.Contracts` (not `Quadra.Shared.Events`) and implemented in `Quadra.Modules.Matches.Persistence`. They are registered in `MatchesModuleExtensions` so that `InGame` can depend on them via DI without any direct project reference to `Quadra.Modules.Matches`.
- **`IPlayerLevelReader` no-op**: The `NoOpPlayerLevelReader` in `Quadra.Infrastructure` returns `"Beginner"` for every player ID. Use `TryAddScoped` in `InGameModuleExtensions` so that a future Profile implementation can override it.
- **`MatchSummary` record**: a minimal projection (`Id`, `OrganizerId`, `Status` as `string`) returned by `IMatchReader`. The InGame module never accesses the `matches` table directly.
- **`team_members.match_id` denormalization**: stored on every `team_members` row to allow the unique constraint `UNIQUE (match_id, player_id)` and efficient queries without joining to `teams`. `TeamMemberConfiguration` sets `HasIndex(t => new { t.MatchId, t.PlayerId }).IsUnique()`.
- **`TeamMember.MoveTo(newTeamId)`**: sets `TeamId = newTeamId`. No `updated_at` column exists on `team_members`.
- **Module boundary**: `Quadra.Modules.InGame` holds no `ProjectReference` to `Quadra.Modules.Matches`. All inter-module communication goes through `Quadra.Shared` interfaces resolved via DI.
- **`InGameDbContext` isolation**: owns only `teams` and `team_members` tables. Future F1.4 tables (`scores`) are added via a separate migration.
- **Event after commit**: `TeamsFormed` is published only after `SaveChangesAsync` succeeds.
- **Serilog**: log `MatchId`, `TeamACount`, `TeamBCount` on draft; log `MatchId`, `PlayerId`, `TargetTeamId` on manual move. Never log player-level data above `Debug`.
- **CancellationToken**: propagated through every async call in handlers, repositories, and interface implementations.
- **`TimeProvider` injection**: inject into handlers; use `TimeProvider.GetUtcNow()` for all `now` timestamps. Register `TimeProvider.System` in `InGameModuleExtensions` via `TryAddSingleton`.
- **Configuration fail-fast**: `Aws:Sqs:TeamsFormedQueueUrl` validated at startup in `InGameModuleExtensions`; missing config throws `InvalidOperationException`.
