# Spec: F1.4 — In-Game: Scoreboard

## Origin
- User Story / Feature from SCOPE: F1.4 — In-Game: Scoreboard
- Layer: 1
- Requested by: Renan Johny Ortega

## Goal
Enable the Organizer to run a live, set-by-set volleyball scoreboard (best of 3 or 5) for a match, recording points in real time and driving the game through the `NotStarted | InProgress | Ended` states, with every change broadcast to connected clients via SignalR.

## Primary module
`Quadra.Modules.InGame`

## Dependent modules (read-only via interface)
- `Quadra.Modules.Matches` — to verify match existence, organizer identity and lifecycle status via `IMatchReader.FindMatchSummaryAsync` (interface declared in `Quadra.Shared.Contracts`, already introduced in F1.3; no new implementation required)
- `Quadra.Modules.Realtime` — to broadcast scoreboard changes to all clients in the match room via SignalR, through the `IMatchRoomNotifier` interface (declared in `Quadra.Shared.Realtime`, introduced in F1.2; this spec adds one method to it)
- `Quadra.Modules.InGame` internal — reuses `ITeamRepository` (from F1.3) to read the two formed teams for a match; no cross-module access

## Database changes

### New tables

#### `scoreboards`
- `id` `uuid` `PRIMARY KEY DEFAULT gen_random_uuid()`
- `match_id` `uuid` `NOT NULL` — app-layer FK to `matches.id`; no DDL FK (module boundary rule)
- `format` `varchar(16)` `NOT NULL` — enum string: `BestOf3 | BestOf5`
- `state` `varchar(16)` `NOT NULL DEFAULT 'NotStarted'` — enum string: `NotStarted | InProgress | Ended`
- `team_a_id` `uuid` `NOT NULL` — app-layer FK to `teams.id` (owned by InGame, F1.3)
- `team_b_id` `uuid` `NOT NULL` — app-layer FK to `teams.id`
- `team_a_sets_won` `smallint` `NOT NULL DEFAULT 0`
- `team_b_sets_won` `smallint` `NOT NULL DEFAULT 0`
- `current_set_number` `smallint` `NOT NULL DEFAULT 0` — `0` before start; `1..5` while playing
- `winner_team_id` `uuid` `NULL` — set only when `state = Ended`; `NULL` on a forced end with equal sets
- `started_at` `timestamptz` `NULL` — set when `state` transitions to `InProgress`
- `ended_at` `timestamptz` `NULL` — set when `state` transitions to `Ended`
- `created_at` `timestamptz` `NOT NULL DEFAULT now()`
- `updated_at` `timestamptz` `NOT NULL DEFAULT now()`

**Constraints:**
- `UNIQUE (match_id)` — at most one scoreboard per match

**Indexes:**
- unique btree on `match_id` (satisfies the constraint and lookups)

#### `scoreboard_sets`
- `id` `uuid` `PRIMARY KEY DEFAULT gen_random_uuid()`
- `scoreboard_id` `uuid` `NOT NULL` — app-layer FK to `scoreboards.id`; no DDL FK
- `match_id` `uuid` `NOT NULL` — denormalized for efficient per-match queries; app-layer FK to `matches.id`
- `set_number` `smallint` `NOT NULL` — `1..5`
- `team_a_points` `smallint` `NOT NULL DEFAULT 0`
- `team_b_points` `smallint` `NOT NULL DEFAULT 0`
- `status` `varchar(16)` `NOT NULL DEFAULT 'InProgress'` — enum string: `InProgress | Finished`
- `is_deciding_set` `boolean` `NOT NULL DEFAULT false` — deciding set (target 15 instead of 25)
- `winner_team_id` `uuid` `NULL` — set when `status = Finished`
- `started_at` `timestamptz` `NOT NULL DEFAULT now()`
- `finished_at` `timestamptz` `NULL`
- `created_at` `timestamptz` `NOT NULL DEFAULT now()`
- `updated_at` `timestamptz` `NOT NULL DEFAULT now()`

**Constraints:**
- `UNIQUE (scoreboard_id, set_number)` — each set number appears once per scoreboard

**Indexes:**
- btree on `scoreboard_id`
- btree on `match_id`

## REST endpoints

### `POST /api/v1/matches/{matchId}/scoreboard`
Creates (prepares) the scoreboard for a match in `NotStarted` state.
- **Auth**: JWT required (`[Authorize]`)
- **Request** (C# record):
  ```csharp
  public record CreateScoreboardRequest(
      string Format); // "BestOf3" | "BestOf5"
  ```
- **Response 201 Created**: `ScoreboardResponse` (see below); `Location: /api/v1/matches/{matchId}/scoreboard`
- **Possible errors**:
  - `400` — validation failure
  - `401` — missing or invalid JWT
  - `403` — caller is not the match organizer
  - `404` — match not found; or teams have not been formed for this match
  - `409` — a scoreboard already exists for this match; or match status is not `Closed`
- **Validation** (FluentValidation `CreateScoreboardRequestValidator`):
  - `Format`: required; must be `BestOf3` or `BestOf5` (case-insensitive)
- **Behavior**:
  1. Extract `callerId` from `User.FindFirst(ClaimTypes.NameIdentifier)?.Value`; return `401` if parse fails.
  2. Call `IMatchReader.FindMatchSummaryAsync(matchId, cancellationToken)`; return `404` if not found.
  3. Verify `callerId == matchSummary.OrganizerId`; return `403` if mismatch.
  4. If `matchSummary.Status != "Closed"` → `409 ConflictProblem("A scoreboard can only be created after the confirmation window closes and teams are formed.")`.
  5. Load teams via `ITeamRepository.ListByMatchAsync(matchId, cancellationToken)`; if fewer than two teams → `404 ProblemDetails("Teams have not been formed for this match yet.")`.
  6. If a `scoreboards` row already exists for `matchId` → `409 ConflictProblem("A scoreboard already exists for this match.")`.
  7. Deterministically resolve `teamAId` and `teamBId` (teams ordered by `name` ascending — "Team A" before "Team B").
  8. Create the `Scoreboard` aggregate via `Scoreboard.Create(matchId, format, teamAId, teamBId, now)` with `state = NotStarted`, `current_set_number = 0`. No sets are created yet.
  9. Persist via `IScoreboardRepository.AddAsync(scoreboard, cancellationToken)`.
  10. Map → `ScoreboardResponse` → `201 Created`.

### `POST /api/v1/matches/{matchId}/scoreboard/start`
Transitions the scoreboard from `NotStarted` to `InProgress` and opens set 1.
- **Auth**: JWT required (`[Authorize]`)
- **Request**: no body
- **Response 200 OK**: `ScoreboardResponse`
- **Possible errors**:
  - `401` — missing or invalid JWT
  - `403` — caller is not the match organizer
  - `404` — match not found; or scoreboard not found for this match
  - `409` — scoreboard state is not `NotStarted`
- **Behavior**:
  1. Extract `callerId` from JWT; return `401` if parse fails.
  2. Call `IMatchReader.FindMatchSummaryAsync(matchId, cancellationToken)`; return `404` if not found.
  3. Verify `callerId == matchSummary.OrganizerId`; return `403` if mismatch.
  4. Load scoreboard via `IScoreboardRepository.FindByMatchAsync(matchId, cancellationToken)`; return `404 ProblemDetails("Scoreboard not found for this match.")` if missing.
  5. If `scoreboard.State != NotStarted` → `409 ConflictProblem("The game has already started or ended.")`.
  6. Call `scoreboard.Start(now)`: sets `State = InProgress`, `StartedAt = now`, `CurrentSetNumber = 1`.
  7. Create the first `ScoreboardSet` via `ScoreboardSet.Create(scoreboardId, matchId, setNumber: 1, isDecidingSet: false, now)`.
  8. Persist scoreboard and set inside a single transaction via `IScoreboardRepository.UpdateAsync(scoreboard, cancellationToken)`.
  9. Publish `MatchStarted` event to SQS via `IEventPublisher` after commit.
  10. Broadcast `ScoreboardUpdatedMessage` to the SignalR match room via `IMatchRoomNotifier.NotifyScoreboardUpdatedAsync`.
  11. Map → `ScoreboardResponse` → `200 OK`.

---

### `POST /api/v1/matches/{matchId}/scoreboard/sets/{setNumber}/points`
Records a single point for one team in the current set. This is the real-time point/set recording endpoint.
- **Auth**: JWT required (`[Authorize]`)
- **Request** (C# record):
  ```csharp
  public record RecordPointRequest(
      Guid TeamId); // must be team_a_id or team_b_id of the scoreboard
  ```
- **Response 200 OK**: `ScoreboardResponse` (full updated state)
- **Possible errors**:
  - `400` — validation failure
  - `401` — missing or invalid JWT
  - `403` — caller is not the match organizer
  - `404` — match not found; or scoreboard not found; or set `{setNumber}` does not exist
  - `409` — scoreboard state is not `InProgress`; or `{setNumber}` is not the current set; or the set is already `Finished`
- **Validation** (FluentValidation `RecordPointRequestValidator`):
  - `TeamId`: must not be empty
- **Behavior**:
  1. Extract `callerId` from JWT; return `401` if parse fails.
  2. Call `IMatchReader.FindMatchSummaryAsync(matchId, cancellationToken)`; return `404` if not found.
  3. Verify `callerId == matchSummary.OrganizerId`; return `403` if mismatch.
  4. Load scoreboard (with sets) via `IScoreboardRepository.FindByMatchAsync(matchId, cancellationToken)`; return `404` if missing.
  5. If `scoreboard.State != InProgress` → `409 ConflictProblem("Points can only be recorded while the game is in progress.")`.
  6. If `TeamId` is neither `team_a_id` nor `team_b_id` → `404 ProblemDetails("Team is not part of this scoreboard.")`.
  7. If `setNumber != scoreboard.CurrentSetNumber` → `409 ConflictProblem("Points can only be recorded for the current set.")`.
  8. Locate the current set; if its `status == Finished` → `409 ConflictProblem("This set is already finished.")`.
  9. Increment `team_a_points` or `team_b_points` by 1 for the scoring team; bump `updated_at`.
  10. Evaluate the set using `VolleyballScoringRules.IsSetWon(...)` (target 25, or 15 for a deciding set; win by ≥ 2, no cap). If won:
      a. Mark set `status = Finished`, `winner_team_id`, `finished_at = now`.
      b. Increment `scoreboard.TeamASetsWon` / `TeamBSetsWon`.
      c. Evaluate the game via `VolleyballScoringRules.SetsToWin(format)` (2 for BestOf3, 3 for BestOf5). If a team reached it → `scoreboard.End(winnerTeamId, now)`: `State = Ended`, `WinnerTeamId`, `EndedAt = now`. Otherwise increment `CurrentSetNumber` and create the next `ScoreboardSet` (marking `is_deciding_set = true` when it is the format's last possible set).
  11. Persist all changes (scoreboard + affected sets) inside a single transaction via `IScoreboardRepository.UpdateAsync`.
  12. If the game ended in step 10c, publish `MatchEnded` to SQS after commit.
  13. Broadcast `ScoreboardUpdatedMessage` to the SignalR match room via `IMatchRoomNotifier.NotifyScoreboardUpdatedAsync`.
  14. Map → `ScoreboardResponse` → `200 OK`.

---

### `POST /api/v1/matches/{matchId}/scoreboard/end`
Force-ends an in-progress game early (e.g., time ran out); the winner is derived from sets won so far.
- **Auth**: JWT required (`[Authorize]`)
- **Request**: no body
- **Response 200 OK**: `ScoreboardResponse`
- **Possible errors**:
  - `401` — missing or invalid JWT
  - `403` — caller is not the match organizer
  - `404` — match not found; or scoreboard not found
  - `409` — scoreboard state is not `InProgress`
- **Behavior**:
  1. Extract `callerId` from JWT; return `401` if parse fails.
  2. Call `IMatchReader.FindMatchSummaryAsync(matchId, cancellationToken)`; return `404` if not found.
  3. Verify `callerId == matchSummary.OrganizerId`; return `403` if mismatch.
  4. Load scoreboard via `IScoreboardRepository.FindByMatchAsync(matchId, cancellationToken)`; return `404` if missing.
  5. If `scoreboard.State != InProgress` → `409 ConflictProblem("Only an in-progress game can be ended.")`.
  6. Compute `winnerTeamId`: the team with more sets won; `null` if equal.
  7. Mark the current unfinished set (if any) `status = Finished` with `winner_team_id = null` (abandoned set) and `finished_at = now`.
  8. Call `scoreboard.End(winnerTeamId, now)`: `State = Ended`, `WinnerTeamId`, `EndedAt = now`.
  9. Persist inside a single transaction via `IScoreboardRepository.UpdateAsync`.
  10. Publish `MatchEnded` to SQS after commit.
  11. Broadcast `ScoreboardUpdatedMessage` to the SignalR match room.
  12. Map → `ScoreboardResponse` → `200 OK`.

### `GET /api/v1/matches/{matchId}/scoreboard`
Returns the full current scoreboard state including all sets.
- **Auth**: JWT required (`[Authorize]`)
- **Response 200 OK**:
  ```csharp
  public record ScoreboardResponse(
      Guid Id,
      Guid MatchId,
      string Format,               // BestOf3 | BestOf5
      string State,                // NotStarted | InProgress | Ended
      Guid TeamAId,
      Guid TeamBId,
      int TeamASetsWon,
      int TeamBSetsWon,
      int CurrentSetNumber,
      Guid? WinnerTeamId,
      IReadOnlyList<ScoreboardSetResponse> Sets,
      DateTimeOffset? StartedAt,
      DateTimeOffset? EndedAt,
      DateTimeOffset CreatedAt,
      DateTimeOffset UpdatedAt);

  public record ScoreboardSetResponse(
      Guid Id,
      int SetNumber,
      int TeamAPoints,
      int TeamBPoints,
      string Status,               // InProgress | Finished
      bool IsDecidingSet,
      Guid? WinnerTeamId,
      DateTimeOffset StartedAt,
      DateTimeOffset? FinishedAt);
  ```
- **Possible errors**:
  - `401` — missing or invalid JWT
  - `404` — match not found; or scoreboard not found for this match
- **Behavior**:
  1. Call `IMatchReader.FindMatchSummaryAsync(matchId, cancellationToken)`; return `404` if not found.
  2. Load scoreboard with sets via `IScoreboardRepository.FindByMatchAsync(matchId, cancellationToken)`; return `404 ProblemDetails("Scoreboard not found for this match.")` if missing.
  3. Map entity → `ScoreboardResponse` (sets ordered by `set_number` ascending) → `200 OK`.

## Acceptance criteria (from SCOPE)
- [ ] **set-by-set scoreboard (best of 3 or 5)**: `POST /scoreboard` with `Format = BestOf3` or `BestOf5` creates a scoreboard; `GET /scoreboard` returns per-set rows; recording points auto-finishes a set at 25 (15 for the deciding set) win-by-2, and the game ends when a team reaches 2 (BestOf3) or 3 (BestOf5) sets won.
- [ ] **real-time point/set recording (via SignalR through `Realtime` module)**: every successful `POST /scoreboard/start`, `POST /scoreboard/sets/{setNumber}/points`, `POST /scoreboard/end` triggers a `MatchHub.ScoreboardUpdated` broadcast to group `match:{matchId}` (verified by asserting `IMatchRoomNotifier.NotifyScoreboardUpdatedAsync` is invoked).
- [ ] **match state (`NotStarted | InProgress | Ended`)**: `GET /scoreboard` returns `NotStarted` after create, `InProgress` after start, and `Ended` after the final set or a forced end; invalid transitions return `409`.

## Out of scope (be explicit)
- **individual stats per play (serve, defense, attack)** — explicitly OUT per SCOPE F1.4 ("these come in v2 (US 1.1 of PDF)"); no per-rally attribution is recorded
- **point replay / rewind** — explicitly OUT per SCOPE F1.4; there is no undo/decrement/history endpoint. Points are increment-only; a mis-tap correction is treated as rewind and is not supported
- Writing to `matches.status` — the `NotStarted | InProgress | Ended` state is the InGame scoreboard state, owned by InGame; the `Matches` module's own lifecycle status (`Draft | Open | Closed | InProgress | Ended | Cancelled`) is not mutated by this module (module boundary rule). Any reflection of game state onto `matches.status` is a Matches/Background-Worker concern reacting to `MatchStarted`/`MatchEnded`
- MVP voting — F1.5
- Match summary aggregation — F1.6
- Point cap / tie-break ceiling (e.g., capping a set at 30) — standard win-by-2 with no cap is used
- More than two teams per match — not in SCOPE (F1.3 forms exactly two teams)
- Distribution of win points / XP — happens in `Gamification` via the Background Worker consuming `MatchEnded`; not part of this spec's synchronous flow

## Implementation notes
- **`VolleyballScoringRules`**: pure, side-effect-free functions, unit-tested in isolation. `TargetForSet` returns 15 when `IsDecidingSet(format, setNumber)` else 25. `IsDecidingSet` is true for set 3 in `BestOf3` and set 5 in `BestOf5`. `SetsToWin` is 2 (`BestOf3`) / 3 (`BestOf5`). `IsSetWon(a, b, target)` = `(a >= target || b >= target) && Math.Abs(a - b) >= 2`. No point cap.
- **Auto set/game progression**: all set-close and game-end evaluation happens synchronously inside `RecordPointHandler` within one transaction; the next set row is created automatically when a set finishes and the game is not yet decided. There is no separate "start next set" endpoint.
- **Deterministic team assignment**: `team_a_id` / `team_b_id` are chosen by ordering the two F1.3 teams by `name` ascending, so results are reproducible in tests.
- **Module boundary**: `Quadra.Modules.InGame` holds no `ProjectReference` to `Quadra.Modules.Matches` or `Quadra.Modules.Realtime`. It depends only on `IMatchReader` (`Quadra.Shared.Contracts`) and `IMatchRoomNotifier` (`Quadra.Shared.Realtime`), both resolved via DI. Teams are read through the InGame-owned `ITeamRepository` from F1.3.
- **`ScoreUpdated` framing**: the ARCHITECTURE "InGame publishes `ScoreUpdated`" responsibility is realized as the real-time `MatchHub.ScoreboardUpdated` SignalR broadcast, not an SQS event. Per-point updates have no asynchronous consumer in the MVP, and the quality heuristic requires every SQS event to have a declared consumer; therefore only `MatchStarted` and `MatchEnded` (both with `Quadra.Workers.Background` as consumer) are published to SQS.
- **`scoreboards` + `scoreboard_sets`**: these two tables jointly realize the InGame `scores` responsibility declared in ARCHITECTURE. The two-table split is required to model set-by-set best-of-N with game-level aggregate state.
- **Concurrency**: point recording is expected to come from a single organizer device; the `UNIQUE (match_id)` constraint on `scoreboards` and `UNIQUE (scoreboard_id, set_number)` on `scoreboard_sets` are last-resort guards. Handle `DbUpdateException` on duplicate scoreboard create and return `409`.
- **Events after commit**: `MatchStarted` and `MatchEnded` are published only after `SaveChangesAsync` succeeds; the SignalR broadcast follows the successful commit as well.
- **`TimeProvider` injection**: reuse the singleton registered in F1.3's `InGameModuleExtensions`; use `TimeProvider.GetUtcNow()` for all `now` timestamps.
- **CancellationToken**: propagated through every async handler, repository and interface call.
- **Serilog**: log `MatchId`, `Format`, `State` on create/start/end; log `MatchId`, `SetNumber`, `ScoringTeamId`, `TeamAPoints`, `TeamBPoints` at `Debug` on each recorded point; log `MatchId`, `WinnerTeamId`, `TeamASetsWon`, `TeamBSetsWon` at `Information` on game end.
- **Configuration fail-fast**: `Aws:Sqs:MatchStartedQueueUrl` and `Aws:Sqs:MatchEndedQueueUrl` are validated at startup in `InGameModuleExtensions`; missing config throws `InvalidOperationException`.
