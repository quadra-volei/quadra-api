# Spec: F1.6 — Match Summary

## Origin
- User Story / Feature from SCOPE: F1.6 — Match Summary
- Layer: 1
- Requested by: Renan Johny Ortega

## Goal
Enable finalizing an ended match into a single immutable record — final set-by-set score, duration, MVP and team composition — retrievable through one endpoint and never editable afterwards.

## Primary module
`Quadra.Modules.Matches`

> Rationale for a single primary module: SCOPE lists F1.6 as `Matches` (orchestrator) + `InGame` + `Gamification`. `Matches` is the protagonist: it owns the match lifecycle and the terminal `Ended` status transition (a gap explicitly left open by F1.4's out-of-scope note), and it persists the immutable summary record. `InGame` is a **read-only source** (final score, teams, MVP) consumed through a `Quadra.Shared.Contracts` interface it exposes — it is not a co-author of this spec. `Gamification` is **not** part of the summary's content (the summary carries final score / duration / MVP / composition, no points or XP); point allocation is the pre-existing async Background-Worker chain reacting to `MatchEnded` / `MvpAwarded` and is out of scope here.

## Dependent modules (read-only via interface)
- `Quadra.Modules.InGame` — to read the finished match's scoreboard (format, sets won, per-set points, winner, start/end times), the two teams' composition, and the MVP voting outcome, via a new `IMatchResultReader.GetMatchResultAsync` interface declared in `Quadra.Shared.Contracts` and implemented in `Quadra.Modules.InGame`. This mirrors — in the opposite direction — the F1.3 pattern where `Matches` implemented `IMatchReader` for `InGame`. No project reference between the two modules; the interface is resolved via DI.
- `Quadra.Modules.Auth` — the FA.1 JWT middleware populates `HttpContext.User` with the caller's `sub`; the Matches module reads the claim, never the `users` table.
- `Quadra.Modules.Gamification` — **not a synchronous dependency**; points/XP allocation happens asynchronously in `Quadra.Workers.Background` reacting to `MatchEnded` / `MvpAwarded` (ARCHITECTURE data flow). No summary content depends on it.

## Database changes

### New tables

#### `match_summaries`
- `id` `uuid` `PRIMARY KEY DEFAULT gen_random_uuid()`
- `match_id` `uuid` `NOT NULL` — app-layer FK to `matches.id`; no DDL FK (module boundary rule)
- `format` `varchar(16)` `NOT NULL` — snapshot of the scoreboard format: `BestOf3 | BestOf5`
- `team_a_id` `uuid` `NOT NULL` — snapshot; app-layer FK to `teams.id` (owned by InGame)
- `team_b_id` `uuid` `NOT NULL` — snapshot; app-layer FK to `teams.id`
- `team_a_sets_won` `smallint` `NOT NULL`
- `team_b_sets_won` `smallint` `NOT NULL`
- `winner_team_id` `uuid` `NULL` — `NULL` when the game ended with equal sets (forced end, F1.4)
- `started_at` `timestamptz` `NOT NULL` — scoreboard start (game duration lower bound)
- `ended_at` `timestamptz` `NOT NULL` — scoreboard end (game duration upper bound)
- `duration_seconds` `integer` `NOT NULL` — precomputed `ended_at - started_at`, in whole seconds
- `mvp_player_id` `uuid` `NULL` — snapshot of the decided MVP; `NULL` when no MVP voting was held or no vote was cast; app-layer FK to `users.id`
- `mvp_vote_count` `smallint` `NULL` — winning MVP's vote count; `NULL` when `mvp_player_id` is `NULL`
- `mvp_total_votes` `smallint` `NOT NULL DEFAULT 0` — total ballots cast in the voting session (0 when no voting)
- `generated_by` `uuid` `NOT NULL` — organizer who finalized the summary; app-layer FK to `users.id`
- `generated_at` `timestamptz` `NOT NULL DEFAULT now()`
- `created_at` `timestamptz` `NOT NULL DEFAULT now()`

> No `updated_at` column — the record is immutable; there is no code path that mutates a `match_summaries` row after insert.

**Constraints:**
- `UNIQUE (match_id)` — at most one summary per match (enforces "cannot be edited afterwards" together with the absence of any update path)

**Indexes:**
- unique btree on `match_id` (satisfies the constraint and lookups)

#### `match_summary_sets`
- `id` `uuid` `PRIMARY KEY DEFAULT gen_random_uuid()`
- `match_summary_id` `uuid` `NOT NULL` — app-layer FK to `match_summaries.id`; no DDL FK
- `match_id` `uuid` `NOT NULL` — denormalized for per-match queries
- `set_number` `smallint` `NOT NULL` — `1..5`
- `team_a_points` `smallint` `NOT NULL`
- `team_b_points` `smallint` `NOT NULL`
- `winner_team_id` `uuid` `NULL` — `NULL` for an abandoned set on a forced end
- `created_at` `timestamptz` `NOT NULL DEFAULT now()`

**Constraints:**
- `UNIQUE (match_summary_id, set_number)`

**Indexes:**
- btree on `match_summary_id`
- btree on `match_id`

#### `match_summary_players`
- `id` `uuid` `PRIMARY KEY DEFAULT gen_random_uuid()`
- `match_summary_id` `uuid` `NOT NULL` — app-layer FK to `match_summaries.id`; no DDL FK
- `match_id` `uuid` `NOT NULL` — denormalized for per-match queries
- `team_id` `uuid` `NOT NULL` — snapshot of the team the player belonged to
- `team_name` `varchar(32)` `NOT NULL` — snapshot of the team name (e.g. `"Team A"`)
- `player_id` `uuid` `NOT NULL` — app-layer FK to `users.id`
- `created_at` `timestamptz` `NOT NULL DEFAULT now()`

**Constraints:**
- `UNIQUE (match_summary_id, player_id)` — a player appears once in a summary

**Indexes:**
- btree on `match_summary_id`
- btree on `match_id`

## REST endpoints

### `POST /api/v1/matches/{matchId}/summary`
Finalizes and persists the immutable match summary by snapshotting the InGame result. Also transitions `matches.status` to `Ended`.
- **Auth**: JWT required (`[Authorize]`)
- **Request**: no body
- **Response 201 Created**: `MatchSummaryResponse` (see `GET`); `Location: /api/v1/matches/{matchId}/summary`
- **Possible errors**:
  - `401` — missing or invalid JWT
  - `403` — caller is not the match organizer
  - `404` — match not found; or no scoreboard exists for this match
  - `409` — the scoreboard is not in `Ended` state; or an MVP voting session exists and is still `Open`; or a summary already exists for this match (immutable — cannot be regenerated)
- **Validation** (FluentValidation): none — no request body.
- **Behavior**:
  1. Extract `callerId` from `User.FindFirst(ClaimTypes.NameIdentifier)?.Value`; return `401` if parse fails.
  2. Load the match via `IMatchRepository.FindByIdAsync(matchId, cancellationToken)`; return `404` if not found.
  3. Verify `callerId == match.OrganizerId`; return `403` if mismatch.
  4. If a `match_summaries` row already exists for `matchId` → `409 ConflictProblem("A summary has already been generated for this match and cannot be regenerated.")`.
  5. Call `IMatchResultReader.GetMatchResultAsync(matchId, cancellationToken)` (implemented by InGame). If `null` → `404 ProblemDetails("No scoreboard has been created for this match.")`.
  6. If `result.ScoreboardState != "Ended"` → `409 ConflictProblem("The match summary can only be generated after the game has ended.")`.
  7. If `result.MvpVotingState == "Open"` → `409 ConflictProblem("Close MVP voting before generating the match summary.")`.
  8. Compute `durationSeconds = (int)(result.EndedAt - result.StartedAt).TotalSeconds` (both non-null when `Ended`).
  9. Build the `MatchSummary` aggregate via `MatchSummary.Generate(match.Id, result, generatedBy: callerId, now)`, including one `MatchSummarySet` per `result.Sets` entry and one `MatchSummaryPlayer` per player across `result.Teams`. Snapshot MVP fields from `result` (`MvpPlayerId`, `MvpVoteCount`, `MvpTotalVotes`).
  10. If `match.Status` is `Closed` or `InProgress`, call `match.MarkEnded(now)` (transitions `matches.status → Ended`, bumps `updated_at`); if already `Ended` leave unchanged; if `Cancelled` → `409 ConflictProblem("A cancelled match cannot be summarized.")`.
  11. Persist the summary aggregate and the (possibly) mutated match inside a single transaction via `IMatchSummaryRepository.AddAsync(summary, cancellationToken)` and `IMatchRepository.UpdateAsync(match, cancellationToken)`.
  12. After commit, publish `MatchSummaryGenerated` to SQS via `IEventPublisher`; and, only when step 10 actually changed the status, publish `MatchStatusChanged` (previous → `Ended`).
  13. Map → `MatchSummaryResponse` → `201 Created`.

---

### `GET /api/v1/matches/{matchId}/summary`
Returns the immutable summary for a match.
- **Auth**: JWT required (`[Authorize]`)
- **Request**: no body
- **Response 200 OK**:
  ```csharp
  public record MatchSummaryResponse(
      Guid Id,
      Guid MatchId,
      string Format,                                   // BestOf3 | BestOf5
      Guid TeamAId,
      Guid TeamBId,
      int TeamASetsWon,
      int TeamBSetsWon,
      Guid? WinnerTeamId,
      DateTimeOffset StartedAt,
      DateTimeOffset EndedAt,
      int DurationSeconds,
      Guid? MvpPlayerId,
      int? MvpVoteCount,
      int MvpTotalVotes,
      IReadOnlyList<MatchSummarySetResponse> Sets,     // ordered by SetNumber ascending
      IReadOnlyList<MatchSummaryTeamResponse> Teams,   // ordered by team name ascending
      DateTimeOffset GeneratedAt);

  public record MatchSummarySetResponse(
      int SetNumber,
      int TeamAPoints,
      int TeamBPoints,
      Guid? WinnerTeamId);

  public record MatchSummaryTeamResponse(
      Guid TeamId,
      string Name,
      IReadOnlyList<Guid> PlayerIds);                  // ordered by PlayerId ascending
  ```
- **Possible errors**:
  - `401` — missing or invalid JWT
  - `404` — match not found; or no summary has been generated for this match
- **Behavior**:
  1. Load the match via `IMatchReader.FindMatchSummaryAsync(matchId, cancellationToken)`; return `404` if not found.
  2. Load the summary (with sets and players) via `IMatchSummaryRepository.FindByMatchAsync(matchId, cancellationToken)`; return `404 ProblemDetails("No summary has been generated for this match yet.")` if missing.
  3. Map entity → `MatchSummaryResponse` (sets ordered by `set_number`; teams grouped and ordered by `team_name`; player IDs ordered by `player_id`) → `200 OK`.

## Acceptance criteria (from SCOPE)
- [ ] **endpoint returning final score, duration, MVP, team composition**: after a scoreboard reaches `Ended`, `POST /api/v1/matches/{matchId}/summary` by the organizer returns `201` and `GET /api/v1/matches/{matchId}/summary` returns `200` with `TeamASetsWon` / `TeamBSetsWon` and per-set `Sets` (final score), `DurationSeconds` (duration), `MvpPlayerId` / `MvpVoteCount` (MVP), and `Teams` with each team's `PlayerIds` (team composition).
- [ ] **immutable record (cannot be edited afterwards)**: a second `POST /api/v1/matches/{matchId}/summary` for a match that already has a summary returns `409`; there is no `PUT`, `PATCH` or `DELETE` on the summary resource, and the `match_summaries` row carries no `updated_at` and no code path mutates it after insert.

## Out of scope (be explicit)
- **shareable image generation (frontend)** — explicitly OUT per SCOPE F1.6; this spec returns structured JSON only, never a rendered image
- **Points / XP / ranking in the summary payload** — allocated asynchronously by `Quadra.Workers.Background` via `Gamification` reacting to `MatchEnded` / `MvpAwarded`; the summary carries no point data
- **Auto-generation of the summary by a scheduler** — a `Quadra.Workers.Background` job could invoke `GenerateMatchSummaryHandler` after `MvpAwarded`; the scheduling mechanism itself is out of scope (same pattern as F1.2/F1.5 window/close handlers). The HTTP path is organizer-driven.
- **Editing / correcting a match result** — the record is immutable; correction is not a feature (consistent with F1.4's no-rewind rule)
- **Player-facing profile match history and aggregated stats** — F2.1 (`Profile`), fed asynchronously by the events above
- **Recomputing the summary if underlying InGame data changed** — InGame data is already immutable after `Ended` (scoreboard, teams) and `Closed` (MVP voting); no recompute path exists
- **Match summaries for cancelled matches** — a `Cancelled` match cannot be summarized (`409`)

## Implementation notes
- **`IMatchResultReader` DTO shape** (declared in `Quadra.Shared.Contracts`, implemented in `Quadra.Modules.InGame`):
  ```csharp
  public sealed record MatchResult(
      Guid MatchId,
      string ScoreboardState,       // NotStarted | InProgress | Ended
      string Format,                // BestOf3 | BestOf5
      Guid TeamAId,
      Guid TeamBId,
      int TeamASetsWon,
      int TeamBSetsWon,
      Guid? WinnerTeamId,
      DateTimeOffset StartedAt,      // scoreboard start; non-null when Ended
      DateTimeOffset EndedAt,        // scoreboard end; non-null when Ended
      IReadOnlyList<MatchResultSet> Sets,
      IReadOnlyList<MatchResultTeam> Teams,
      string MvpVotingState,        // None | Open | Closed
      Guid? MvpPlayerId,
      int? MvpVoteCount,
      int MvpTotalVotes);

  public sealed record MatchResultSet(int SetNumber, int TeamAPoints, int TeamBPoints, Guid? WinnerTeamId);
  public sealed record MatchResultTeam(Guid TeamId, string Name, IReadOnlyList<Guid> PlayerIds);
  ```
- **Dependency direction / boundaries**: `Quadra.Modules.Matches` holds **no** `ProjectReference` to `Quadra.Modules.InGame`. It consumes `IMatchResultReader` (declared in `Quadra.Shared.Contracts`) resolved via DI; the implementation lives in and is registered by the InGame module. This is the exact inverse of F1.3, where `Matches` implemented `IMatchReader`/`IConfirmedPlayersReader` for `InGame`. No cross-module JOINs and no cross-module table access on either side.
- **`MatchResultReader` composition (InGame side)**: reuses the InGame-owned repositories only — `IScoreboardRepository.FindByMatchAsync` (scoreboard + sets, F1.4), `ITeamRepository.ListByMatchAsync` (teams + members, F1.3), and `IMvpVotingRepository.FindByMatchAsync` (voting + decided MVP, F1.5). Returns `null` when no scoreboard exists. `MvpVotingState = "None"` when no voting session exists.
- **Snapshot semantics**: `GenerateMatchSummaryHandler` copies the InGame result into the Matches-owned `match_summaries` tree. This is a genuine snapshot (a Matches-owned copy), not a live view — it is what makes the record self-contained and immutable even though the source lives in another module.
- **Immutability enforcement**: (a) `UNIQUE (match_id)` on `match_summaries`; (b) `409` on the existence check in step 4; (c) no update/delete endpoint; (d) no `updated_at` column and no repository method that mutates a summary. Handle `DbUpdateException` on the unique constraint as a last-resort race guard → `409`.
- **`matches.status → Ended` transition**: F1.4 explicitly deferred writing `Ended` onto `matches.status` to "a Matches/Background-Worker concern". F1.6 fulfills that on the Matches side via `Match.MarkEnded(now)`, keeping `matches.status` ownership inside `Matches` (module boundary). The `InProgress` transition remains a separate Background-Worker concern reacting to `MatchStarted` and is not in this spec.
- **Duration**: computed once as whole seconds from the scoreboard's `StartedAt`/`EndedAt` and stored in `duration_seconds` so the immutable record is self-contained (no dependency on re-reading InGame to render duration).
- **`WinnerTeamId` in the event**: `MatchSummaryGenerated.WinnerTeamId` uses `Guid.Empty` for a level (no-winner) game because the SQS payload keeps a non-nullable field for consumer simplicity; the persisted column and the REST response keep the nullable `winner_team_id` / `WinnerTeamId`.
- **Events after commit**: both `MatchSummaryGenerated` and (conditionally) `MatchStatusChanged` are published only after `SaveChangesAsync` succeeds.
- **`TimeProvider` injection**: reuse the singleton registered in F1.1's `MatchesModuleExtensions`; use `TimeProvider.GetUtcNow()` for `generated_at` and the `MarkEnded` timestamp.
- **CancellationToken**: propagated through every async handler, repository and interface call.
- **Controller thinness**: `MatchSummaryController` actions call the handler and map exceptions to ProblemDetails; no business logic.
- **Serilog**: log `MatchId`, `WinnerTeamId`, `MvpPlayerId`, `DurationSeconds` at `Information` on generate; never log player IDs above `Debug`.
- **Configuration fail-fast**: `Aws:Sqs:MatchSummaryGeneratedQueueUrl` validated at startup in `MatchesModuleExtensions`; missing config throws `InvalidOperationException`.
