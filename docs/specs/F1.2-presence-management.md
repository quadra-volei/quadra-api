# Spec: F1.2 — Presence Management

## Origin
- User Story / Feature from SCOPE: F1.2 — Presence Management
- Layer: 1
- Requested by: Renan Johny Ortega

## Goal
Enable players to confirm or decline their presence in a match, with automatic waiting list management and automatic release of unconfirmed Regular slots to DropIns after the confirmation window closes.

## Primary module
`Quadra.Modules.Matches`

## Dependent modules (read-only via interface)
- `Quadra.Modules.Realtime` — to broadcast presence changes to all clients connected to a match room via SignalR
- `Quadra.Modules.Notifications` — consumes `MatchWindowOpened` and `PresenceConfirmed` events to deliver in-app push notifications (no direct call; event-driven only)

## Database changes

### New tables

#### `match_presences`
- `id` `uuid` `PRIMARY KEY DEFAULT gen_random_uuid()`
- `match_id` `uuid` `NOT NULL` — app-layer FK to `matches.id`; no DDL FK (module boundary rule)
- `player_id` `uuid` `NOT NULL` — app-layer FK to `users.id`; no DDL FK
- `player_type` `varchar(16)` `NOT NULL` — enum string: `Regular | DropIn`
- `status` `varchar(16)` `NOT NULL DEFAULT 'Pending'` — enum string: `Confirmed | Declined | Pending`
- `confirmed_at` `timestamptz` `NULL` — set when status transitions to `Confirmed`
- `created_at` `timestamptz` `NOT NULL DEFAULT now()`
- `updated_at` `timestamptz` `NOT NULL DEFAULT now()`

**Constraints:**
- `UNIQUE (match_id, player_id)` — a player may have only one presence row per match

**Indexes:**
- btree on `match_id`
- btree on `player_id`
- btree on `(match_id, status)`
- btree on `(match_id, player_type)`

#### `waiting_list`
- `id` `uuid` `PRIMARY KEY DEFAULT gen_random_uuid()`
- `match_id` `uuid` `NOT NULL` — app-layer FK to `matches.id`; no DDL FK
- `player_id` `uuid` `NOT NULL` — app-layer FK to `users.id`; no DDL FK
- `player_type` `varchar(16)` `NOT NULL` — enum string: `Regular | DropIn`
- `position` `integer` `NOT NULL` — 1-based ordering within the waiting list for a given match; lower = higher priority
- `created_at` `timestamptz` `NOT NULL DEFAULT now()`

**Constraints:**
- `UNIQUE (match_id, player_id)` — a player may appear only once in the waiting list per match
- `UNIQUE (match_id, position)` — positions are unique within a match

**Indexes:**
- btree on `match_id`
- btree on `(match_id, position)` — for ordered promotion queries

### New columns in existing tables
- `matches.released_drop_in_slots` `smallint` `NULL` — set by `CloseMatchWindowHandler` to store how many Regular slots were freed up for DropIn use

### Migrations required
- `<TimestampPrefix>_CreateMatchPresencesAndWaitingListTables` — generated under `src/Quadra.Modules.Matches/Migrations/`

## REST endpoints

### `POST /api/v1/matches/{id}/presences`
- **Auth**: JWT required (`[Authorize]`)
- **Request** (C# record):
  ```csharp
  public record AddPresenceRequest(
      Guid PlayerId,
      string PlayerType); // "Regular" | "DropIn"
  ```
- **Response 201 Created**:
  ```csharp
  public record PresenceResponse(
      Guid Id,
      Guid MatchId,
      Guid PlayerId,
      string PlayerType,
      string Status,
      DateTimeOffset? ConfirmedAt,
      DateTimeOffset CreatedAt,
      DateTimeOffset UpdatedAt);
  ```
- **Possible errors**:
  - `400` — validation failure
  - `401` — missing or invalid JWT
  - `403` — caller is not the match organizer
  - `404` — match not found
  - `409` — player already has a presence row for this match; or match status is not `Draft` or `Open`; or `windowClosesAt` has already passed
- **Validation** (FluentValidation `AddPresenceRequestValidator`):
  - `PlayerId`: must not be empty
  - `PlayerType`: required; must be `Regular` or `DropIn` (case-insensitive)
- **Behavior**:
  1. Extract `callerId` from `User.FindFirst(ClaimTypes.NameIdentifier)?.Value`; return `401` if parse fails.
  2. Load match by `id`; return `404` if not found.
  3. Verify `callerId == match.OrganizerId`; return `403` if mismatch.
  4. If match status is not `Draft` or `Open` → `409 ConflictProblem("Match is not in a state that accepts new presences.")`.
  5. If `TimeProvider.GetUtcNow() > match.WindowClosesAt` → `409 ConflictProblem("Confirmation window has already closed.")`.
  6. If a `match_presences` row already exists for `(match_id, player_id)` → `409 ConflictProblem("Player is already on the presence list.")`.
  7. Call `IPresenceRepository.AddAsync(presence, cancellationToken)` where `presence` has `status = Pending`.
  8. Broadcast `PresenceUpdated` message to the match SignalR room via `IMatchRoomNotifier`.
  9. Return `201 Created` with `PresenceResponse` body and `Location: /api/v1/matches/{id}/presences/{presenceId}` header.

### `PUT /api/v1/matches/{id}/presences/me`
- **Auth**: JWT required (`[Authorize]`)
- **Request** (C# record):
  ```csharp
  public record UpdateMyPresenceRequest(
      string Status); // "Confirmed" | "Declined"
  ```
- **Response 200 OK**:
  ```csharp
  public record PresenceResponse(
      Guid Id,
      Guid MatchId,
      Guid PlayerId,
      string PlayerType,
      string Status,
      DateTimeOffset? ConfirmedAt,
      DateTimeOffset CreatedAt,
      DateTimeOffset UpdatedAt);
  ```
- **Possible errors**:
  - `400` — validation failure
  - `401` — missing or invalid JWT
  - `404` — match not found; or caller has no presence row for this match
  - `409` — window is not open for the caller's player type; or match is not `Open`; or slot limit reached (player is added to waiting list instead — see Behavior)
- **Validation** (FluentValidation `UpdateMyPresenceRequestValidator`):
  - `Status`: required; must be `Confirmed` or `Declined` (case-insensitive)
- **Behavior**:
  1. Extract `callerId` from JWT; return `401` if parse fails.
  2. Load match by `id`; return `404` if not found.
  3. Load presence row where `match_id = id AND player_id = callerId`; return `404 ProblemDetails("Presence not found.")` if missing.
  4. Determine window eligibility:
     - If `presence.PlayerType == Regular`: window must be open (`WindowOpensAt <= now <= WindowClosesAt`) AND match status must be `Open`. Otherwise → `409 ConflictProblem("Confirmation window is not open.")`.
     - If `presence.PlayerType == DropIn`: `now > WindowClosesAt` AND match status must be `Closed`. Otherwise → `409 ConflictProblem("DropIn slots are not yet available.")`.
  5. If `Status == "Declined"`:
     a. Set `presence.Status = Declined`, `presence.UpdatedAt = now`.
     b. Persist via `IPresenceRepository.UpdateAsync`.
     c. If `presence.PlayerType == Regular`: call `PromoteFirstWaiterAsync(matchId, PlayerType.Regular, cancellationToken)` — promotes the first Regular in `waiting_list` (lowest `position`) by creating a `Pending` presence row for them and removing their waiting list entry. If no Regular waiter exists, do nothing.
     d. Publish `PresenceUpdated` (see SQS events).
     e. Broadcast `PresenceUpdated` to SignalR match room.
     f. Return `200 OK` with updated `PresenceResponse`.
  6. If `Status == "Confirmed"`:
     a. Count `confirmed_count`: number of rows in `match_presences` where `match_id = id AND player_type = presence.PlayerType AND status = Confirmed`.
     b. Determine `slot_limit`:
        - Regular → `match.RegularSlots`
        - DropIn → `match.DropInSlots + (match.ReleasedDropInSlots ?? 0)`
     c. If `confirmed_count >= slot_limit`:
        - Check if player already on waiting list → if yes, return `409 ConflictProblem("All slots are full; you are already on the waiting list.")`.
        - Compute next `position = MAX(position) + 1` for the match (or `1` if none exist).
        - Insert row in `waiting_list`.
        - Return `409 ConflictProblem("All slots are full. You have been added to the waiting list.")` with body including waiting list position.
     d. Set `presence.Status = Confirmed`, `presence.ConfirmedAt = now`, `presence.UpdatedAt = now`.
     e. Persist via `IPresenceRepository.UpdateAsync`.
     f. Publish `PresenceConfirmed` event to SQS via `IEventPublisher`.
     g. Broadcast `PresenceUpdated` to SignalR match room.
     h. Return `200 OK` with updated `PresenceResponse`.

### `GET /api/v1/matches/{id}/presences`
- **Auth**: JWT required (`[Authorize]`)
- **Response 200 OK**:
  ```csharp
  public record PresenceListResponse(
      IReadOnlyList<PresenceResponse> Confirmed,
      IReadOnlyList<PresenceResponse> Pending,
      IReadOnlyList<PresenceResponse> Declined,
      IReadOnlyList<WaitingListEntryResponse> WaitingList,
      int ConfirmedCount,
      int RegularSlots,
      int DropInSlots);

  public record WaitingListEntryResponse(
      Guid PlayerId,
      string PlayerType,
      int Position,
      DateTimeOffset CreatedAt);
  ```
- **Possible errors**:
  - `401` — missing or invalid JWT
  - `404` — match not found
- **Behavior**:
  1. Load match by `id`; return `404` if not found.
  2. Load all `match_presences` rows for `match_id = id`, ordered by `created_at ASC`.
  3. Load all `waiting_list` rows for `match_id = id`, ordered by `position ASC`.
  4. Partition presences into `Confirmed`, `Pending`, `Declined` lists.
  5. Map waiting list rows to `WaitingListEntryResponse`.
  6. Return `200 OK`.

---

### `DELETE /api/v1/matches/{id}/presences/{playerId}`
- **Auth**: JWT required (`[Authorize]`)
- **Response 204 No Content**
- **Possible errors**:
  - `401` — missing or invalid JWT
  - `403` — caller is not the match organizer
  - `404` — match not found; or presence row not found
  - `409` — match status is not `Draft` (organizer may only remove a Regular before the window opens)
- **Behavior**:
  1. Extract `callerId` from JWT; return `401` if parse fails.
  2. Load match by `id`; return `404` if not found.
  3. Verify `callerId == match.OrganizerId`; return `403` if mismatch.
  4. If match status is not `Draft` → `409 ConflictProblem("Players can only be removed before the confirmation window opens.")`.
  5. Load presence where `match_id = id AND player_id = playerId`; return `404` if not found.
  6. Delete the presence row via `IPresenceRepository.DeleteAsync`.
  7. Return `204 No Content`.

## SQS events

### Published

- `PresenceConfirmed` — fired when a player successfully confirms their presence (step 6f of `PUT /presences/me`)
  - Payload:
    ```csharp
    public sealed record PresenceConfirmed(
        Guid MatchId,
        Guid PlayerId,
        string PlayerType,
        DateTimeOffset ConfirmedAt,
        DateTimeOffset OccurredAt);
    ```
  - Declared consumers: `Quadra.Modules.Notifications` — stores an in-app notification record for the player

- `MatchWindowOpened` — fired by `OpenMatchWindowHandler` after it transitions match status to `Open`.
  - Payload:
    ```csharp
    public sealed record MatchWindowOpened(
        Guid MatchId,
        Guid OrganizerId,
        DateTimeOffset WindowClosesAt,
        IReadOnlyList<Guid> PendingPlayerIds,
        DateTimeOffset OccurredAt);
    ```
  - Declared consumers: `Quadra.Workers.Background` — dispatches push notification requests for each player in `PendingPlayerIds` by publishing `NotificationRequested` events to the Notification Worker

- `MatchWindowClosed` — fired by `CloseMatchWindowHandler` after it transitions match status to `Closed` and releases DropIn slots.
  - Payload:
    ```csharp
    public sealed record MatchWindowClosed(
        Guid MatchId,
        Guid OrganizerId,
        int ReleasedDropInSlots,
        DateTimeOffset OccurredAt);
    ```
  - Declared consumers: `Quadra.Workers.Background` — notifies the organizer that the window closed and dispatches push notification requests via `NotificationRequested`

The existing `MatchStatusChanged` event (already in `Quadra.Shared`) is **not** published by `OpenMatchWindowHandler` or `CloseMatchWindowHandler`. Those transitions are fully represented by `MatchWindowOpened` and `MatchWindowClosed` respectively, which carry richer payloads and have explicit consumers. `MatchStatusChanged` remains in use only for the `Cancelled` transition introduced in F1.1.

## Acceptance criteria (from SCOPE)

- [ ] List of Regulars with status `Confirmed | Declined | Pending` is returned by `GET /api/v1/matches/{id}/presences`.
- [ ] Push notification when window opens is delegated to `Notifications` module via the `MatchWindowOpened` SQS event (verified by asserting event publication from `OpenMatchWindowHandler`).
- [ ] Automatic waiting list when slots exceeded: when a player confirms and all slots of their type are taken, a row is inserted in `waiting_list` and the response returns `409` with the waiting list position.
- [ ] Automatic slot release to DropIns after `windowClosesAt`: after the window closes, a DropIn player who attempts to confirm when all original `DropInSlots` are already taken but at least one Regular slot was left unconfirmed receives HTTP 200 (successfully confirmed) rather than HTTP 409 (slot full).

## Out of scope (be explicit)

- Partial confirmation (e.g. "I'll arrive late") — explicitly OUT per SCOPE F1.2
- Direct player-to-player substitution — explicitly OUT per SCOPE F1.2
- Organizer editing an existing presence row on behalf of a player (only the player can change their own status)
- Automatic push delivery to devices — handled by `Notification Worker`; this spec only publishes events to SQS
- Team drafting or scoreboard — F1.3 / F1.4
- DropIn discovery of open matches — F1.7 (`Geo` module)
- Recurring match instance generation (each occurrence as a separate match row) — deferred
- Organizer removing a Regular after the window has opened — `409` by design; not in SCOPE

## Implementation notes

- **`ReleasedDropInSlots` on `Match`**: add a nullable `short? ReleasedDropInSlots` column to the `matches` table. Set by `CloseMatchWindowHandler` so subsequent DropIn confirmations can compute their effective slot limit without re-querying presences.
- **`Match.OpenWindow(now)`**: validates transition `Draft → Open`; throws `InvalidMatchStatusTransitionException` if not `Draft`. Sets `Status = Open`, `UpdatedAt = now`.
- **`Match.CloseWindow(releasedSlots, now)`**: validates transition `Open → Closed`; throws `InvalidMatchStatusTransitionException` if not `Open`. Sets `Status = Closed`, `ReleasedDropInSlots = releasedSlots`, `UpdatedAt = now`.
- **DropIn effective slot limit**: `match.DropInSlots + (match.ReleasedDropInSlots ?? 0)`.
- **Waiting list promotion on decline**: synchronous within the HTTP request (same transaction). The promoted player gets a `Pending` row.
- **DropIn promotion at window close**: `CloseMatchWindowHandler` iterates waiting DropIns (ordered by `position ASC`) and promotes as many as `released_drop_in_slots` allows by creating `Pending` presence rows.
- **`IMatchRoomNotifier` interface**: declared in `Quadra.Shared`; implemented in `Quadra.Modules.Realtime`. The Matches module depends on the interface only — never on the Realtime module directly.
- **Concurrency**: the unique constraint on `match_presences(match_id, player_id)` provides last-resort protection; handle `DbUpdateException` for duplicate key and return `409`.
- **Serilog**: log `MatchId`, `PlayerId`, `PlayerType`, `Status` on every presence transition.
- **Event ordering**: `PresenceConfirmed` is published only after `SaveChangesAsync` succeeds.
- **`TimeProvider` injection**: reuse the singleton registered in F1.1.
- **Background Worker integration**: `OpenMatchWindowHandler` and `CloseMatchWindowHandler` are application handlers in the Matches module. The scheduling mechanism (how the worker calls them) is out of scope here.
