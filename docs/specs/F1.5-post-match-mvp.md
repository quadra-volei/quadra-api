# Spec: F1.5 — Post-Match: MVP

## Origin
- User Story / Feature from SCOPE: F1.5 — Post-Match: MVP
- Layer: 1
- Requested by: Renan Johny Ortega

## Goal
Enable match participants to each cast one vote (never for themselves) for the match's Most Valuable Player within an Organizer-set deadline (default 24h), and automatically select the MVP from those votes when voting closes.

## Primary module
`Quadra.Modules.InGame`

> Rationale for a single primary module: SCOPE lists F1.5 as `InGame` (voting) + `Gamification` (point allocation). The `Gamification` point allocation (+25 per PRODUCT.md) is **not** part of this synchronous flow — it happens downstream in `Quadra.Workers.Background` consuming the `MvpAwarded` event and calling `Gamification.DistributePoints`, exactly as described in ARCHITECTURE's "player voted MVP" data flow. This spec therefore has exactly one protagonist module (`InGame`); `Gamification` is a declared async consumer, not a co-author.

## Dependent modules (read-only via interface)
- `Quadra.Modules.Matches` — to verify match existence and organizer identity via `IMatchReader.FindMatchSummaryAsync` (interface in `Quadra.Shared.Contracts`, introduced in F1.3; no new implementation required)
- `Quadra.Modules.InGame` internal — reuses `ITeamRepository` (from F1.3) to read the match's team members (the set of eligible voters and candidates) and `IScoreboardRepository` (from F1.4) to verify the scoreboard is in the `Ended` state; both are InGame-owned, no cross-module access
- `Quadra.Modules.Gamification` — **not a synchronous dependency**; it allocates the +25 MVP points asynchronously via `Quadra.Workers.Background` consuming the `MvpAwarded` event published by this spec

## Database changes

### New tables

#### `mvp_votings`
- `id` `uuid` `PRIMARY KEY DEFAULT gen_random_uuid()`
- `match_id` `uuid` `NOT NULL` — app-layer FK to `matches.id`; no DDL FK (module boundary rule)
- `state` `varchar(16)` `NOT NULL DEFAULT 'Open'` — enum string: `Open | Closed`
- `deadline_at` `timestamptz` `NOT NULL` — Organizer-set; defaults to `opened_at + 24h`
- `total_votes` `smallint` `NOT NULL DEFAULT 0` — cached count of cast votes
- `mvp_player_id` `uuid` `NULL` — set only when `state = Closed` and at least one vote was cast; app-layer FK to `users.id`; no DDL FK
- `mvp_vote_count` `smallint` `NULL` — winning candidate's vote count; set only when `state = Closed` with a decided MVP
- `opened_at` `timestamptz` `NOT NULL DEFAULT now()`
- `closed_at` `timestamptz` `NULL` — set when `state` transitions to `Closed`
- `created_at` `timestamptz` `NOT NULL DEFAULT now()`
- `updated_at` `timestamptz` `NOT NULL DEFAULT now()`

**Constraints:**
- `UNIQUE (match_id)` — at most one voting session per match

**Indexes:**
- unique btree on `match_id` (satisfies the constraint and lookups)
- btree on `(state, deadline_at)` — for the Background Worker's scheduled query of open votings past their deadline

#### `mvp_votes`
- `id` `uuid` `PRIMARY KEY DEFAULT gen_random_uuid()`
- `voting_id` `uuid` `NOT NULL` — app-layer FK to `mvp_votings.id`; no DDL FK
- `match_id` `uuid` `NOT NULL` — denormalized for efficient per-match queries; app-layer FK to `matches.id`; no DDL FK
- `voter_player_id` `uuid` `NOT NULL` — app-layer FK to `users.id`; no DDL FK
- `voted_player_id` `uuid` `NOT NULL` — app-layer FK to `users.id`; no DDL FK
- `created_at` `timestamptz` `NOT NULL DEFAULT now()`
- `updated_at` `timestamptz` `NOT NULL DEFAULT now()`

**Constraints:**
- `UNIQUE (match_id, voter_player_id)` — a participant may hold only one vote per match
- `CHECK (voter_player_id <> voted_player_id)` — DB-level guard against self-voting (last-resort; primary enforcement is in the handler)

**Indexes:**
- btree on `voting_id`
- btree on `(match_id, voted_player_id)` — for tally aggregation
- unique btree on `(match_id, voter_player_id)` (satisfies the constraint)

### New columns in existing tables
None.

## REST endpoints

### `POST /api/v1/matches/{matchId}/mvp-voting`
Opens the MVP voting session for an ended match.
- **Auth**: JWT required (`[Authorize]`)
- **Request** (C# record):
  ```csharp
  public record OpenMvpVotingRequest(
      DateTimeOffset? DeadlineAt); // optional; null => opened_at + 24h
  ```
- **Response 201 Created**: `MvpVotingResponse` (see `GET`); `Location: /api/v1/matches/{matchId}/mvp-voting`
- **Possible errors**:
  - `400` — validation failure
  - `401` — missing or invalid JWT
  - `403` — caller is not the match organizer
  - `404` — match not found; or scoreboard not found for this match
  - `409` — scoreboard state is not `Ended`; or a voting session already exists for this match
- **Validation** (FluentValidation `OpenMvpVotingRequestValidator`):
  - `DeadlineAt`: when provided, must be strictly in the future (`> TimeProvider.GetUtcNow()`)
- **Behavior**:
  1. Extract `callerId` from `User.FindFirst(ClaimTypes.NameIdentifier)?.Value`; return `401` if parse fails.
  2. Call `IMatchReader.FindMatchSummaryAsync(matchId, cancellationToken)`; return `404` if not found.
  3. Verify `callerId == matchSummary.OrganizerId`; return `403` if mismatch.
  4. Load scoreboard via `IScoreboardRepository.FindByMatchAsync(matchId, cancellationToken)`; if missing or `State != Ended` → `409 ConflictProblem("MVP voting can only be opened after the match has ended.")`.
  5. If an `mvp_votings` row already exists for `matchId` → `409 ConflictProblem("An MVP voting session already exists for this match.")`.
  6. Compute `deadlineAt = request.DeadlineAt ?? now.AddHours(24)`.
  7. Create the `MvpVoting` aggregate via `MvpVoting.Open(matchId, deadlineAt, now)` with `state = Open`, `total_votes = 0`.
  8. Persist via `IMvpVotingRepository.AddAsync(voting, cancellationToken)`.
  9. Map → `MvpVotingResponse` → `201 Created`.

---

### `POST /api/v1/matches/{matchId}/mvp-voting/votes`
Casts (or replaces, while Open) the caller's single MVP vote.
- **Auth**: JWT required (`[Authorize]`)
- **Request** (C# record):
  ```csharp
  public record CastMvpVoteRequest(
      Guid VotedPlayerId);
  ```
- **Response 200 OK**:
  ```csharp
  public record MvpVoteResponse(
      Guid MatchId,
      Guid VoterPlayerId,
      Guid VotedPlayerId,
      DateTimeOffset CreatedAt,
      DateTimeOffset UpdatedAt);
  ```
- **Possible errors**:
  - `400` — validation failure
  - `401` — missing or invalid JWT
  - `403` — caller is not a participant (team member) of this match
  - `404` — match not found; or voting session not found; or `VotedPlayerId` is not a participant of this match
  - `409` — voting state is not `Open`; or the deadline has passed; or the caller attempts to vote for themselves
- **Validation** (FluentValidation `CastMvpVoteRequestValidator`):
  - `VotedPlayerId`: must not be empty
- **Behavior**:
  1. Extract `callerId` from JWT; return `401` if parse fails.
  2. Call `IMatchReader.FindMatchSummaryAsync(matchId, cancellationToken)`; return `404` if not found.
  3. Load voting via `IMvpVotingRepository.FindByMatchAsync(matchId, cancellationToken)`; return `404 ProblemDetails("MVP voting has not been opened for this match.")` if missing.
  4. If `voting.State != Open` → `409 ConflictProblem("Voting is closed.")`.
  5. If `now > voting.DeadlineAt` → `409 ConflictProblem("The voting deadline has passed.")` (defense in depth; the Background Worker is expected to have closed it — see Implementation notes).
  6. Load team members via `ITeamRepository.ListByMatchAsync(matchId, cancellationToken)`; build the participant set of `player_id`s.
  7. If `callerId` is not in the participant set → `403 ProblemDetails("Only match participants can vote.")`.
  8. If `VotedPlayerId == callerId` → `409 ConflictProblem("You cannot vote for yourself.")`.
  9. If `VotedPlayerId` is not in the participant set → `404 ProblemDetails("The voted player is not a participant of this match.")`.
  10. Upsert the caller's vote via `IMvpVotingRepository.CastVoteAsync(votingId, matchId, callerId, VotedPlayerId, now, cancellationToken)`:
      - If no `mvp_votes` row exists for `(match_id, voter_player_id = callerId)`: insert it and increment `mvp_votings.total_votes`.
      - If a row exists: update `voted_player_id` and `updated_at` (still one vote — no `total_votes` change).
      - All changes committed in a single transaction.
  11. Map → `MvpVoteResponse` → `200 OK`.

### `POST /api/v1/matches/{matchId}/mvp-voting/close`
Closes voting and selects the MVP. Invoked by the Organizer for an early manual close; the same handler is invoked by the Background Worker at the deadline (scheduling out of scope — see Implementation notes).
- **Auth**: JWT required (`[Authorize]`)
- **Request**: no body
- **Response 200 OK**: `MvpVotingResponse`
- **Possible errors**:
  - `401` — missing or invalid JWT
  - `403` — caller is not the match organizer
  - `404` — match not found; or voting session not found
  - `409` — voting state is not `Open`
- **Behavior**:
  1. Extract `callerId` from JWT; return `401` if parse fails.
  2. Call `IMatchReader.FindMatchSummaryAsync(matchId, cancellationToken)`; return `404` if not found.
  3. Verify `callerId == matchSummary.OrganizerId`; return `403` if mismatch.
  4. Load voting (with votes) via `IMvpVotingRepository.FindByMatchAsync(matchId, cancellationToken)`; return `404` if missing.
  5. If `voting.State != Open` → `409 ConflictProblem("Voting is already closed.")`.
  6. Tally votes: group `mvp_votes` by `voted_player_id`, count each. Determine the winner using `MvpSelectionRules.SelectWinner(tallies)` (highest count; ties broken deterministically by lowest `voted_player_id`). If there are zero votes, `mvpPlayerId = null`, `mvpVoteCount = null`.
  7. Call `voting.Close(mvpPlayerId, mvpVoteCount, now)`: `State = Closed`, `ClosedAt = now`, `MvpPlayerId`, `MvpVoteCount`.
  8. Persist via `IMvpVotingRepository.UpdateAsync(voting, cancellationToken)`.
  9. If `mvpPlayerId != null`, publish `MvpAwarded` to SQS via `IEventPublisher` **after commit**.
  10. Map → `MvpVotingResponse` → `200 OK`.

---

### `GET /api/v1/matches/{matchId}/mvp-voting`
Returns the current voting state. Per-candidate tallies are revealed only once voting is `Closed` (to avoid influencing votes while `Open`).
- **Auth**: JWT required (`[Authorize]`)
- **Response 200 OK**:
  ```csharp
  public record MvpVotingResponse(
      Guid Id,
      Guid MatchId,
      string State,                          // Open | Closed
      DateTimeOffset DeadlineAt,
      int TotalVotes,
      bool CallerHasVoted,
      Guid? MvpPlayerId,                     // null until Closed with a decided MVP
      int? MvpVoteCount,
      IReadOnlyList<MvpVoteTally> Results,   // empty while Open; populated when Closed
      DateTimeOffset OpenedAt,
      DateTimeOffset? ClosedAt,
      DateTimeOffset CreatedAt,
      DateTimeOffset UpdatedAt);

  public record MvpVoteTally(
      Guid PlayerId,
      int Votes);
  ```
- **Possible errors**:
  - `401` — missing or invalid JWT
  - `404` — match not found; or voting session not found for this match
- **Behavior**:
  1. Extract `callerId` from JWT; return `401` if parse fails.
  2. Call `IMatchReader.FindMatchSummaryAsync(matchId, cancellationToken)`; return `404` if not found.
  3. Load voting (with votes) via `IMvpVotingRepository.FindByMatchAsync(matchId, cancellationToken)`; return `404 ProblemDetails("MVP voting has not been opened for this match.")` if missing.
  4. Set `CallerHasVoted` = whether an `mvp_votes` row exists for `(match_id, voter_player_id = callerId)`.
  5. If `State == Closed`, compute `Results` (tallies grouped by `voted_player_id`, ordered by `Votes` descending then `PlayerId` ascending); otherwise `Results` is empty.
  6. Map → `MvpVotingResponse` → `200 OK`.

## Acceptance criteria (from SCOPE)
- [ ] **each player votes for ONE name (cannot self-vote)**: `POST /api/v1/matches/{matchId}/mvp-voting/votes` accepts a single `VotedPlayerId` from a participant, is enforced to one vote per voter by `UNIQUE (match_id, voter_player_id)`, rejects a self-vote (`VotedPlayerId == callerId`) with `409`, and rejects a non-participant voter with `403`.
- [ ] **automatic MVP selection from votes**: `POST /api/v1/matches/{matchId}/mvp-voting/close` tallies all votes and deterministically selects the highest-voted participant as `MvpPlayerId` (ties broken by lowest `PlayerId`); with zero votes `MvpPlayerId` is `null` and no `MvpAwarded` is published.
- [ ] **voting deadline (set by Organizer; default 24h)**: `POST /api/v1/matches/{matchId}/mvp-voting` persists `deadline_at` from the request when provided, and defaults it to `opened_at + 24h` when omitted; votes cast after `deadline_at` are rejected with `409`.

## Out of scope (be explicit)
- **multiple award categories (best serve, best defense, etc.)** — explicitly OUT per SCOPE F1.5; there is a single MVP award only
- **Point allocation (+25 to the MVP)** — happens in `Gamification` via `Quadra.Workers.Background` consuming `MvpAwarded`; not part of this spec's synchronous flow (ARCHITECTURE data flow)
- **In-app / push notification of the MVP result** — handled by the Background Worker and `Notifications` module reacting to `MvpAwarded`; this spec only publishes the event
- **Profile stat updates (MVPs received / level recalculation)** — `Profile` reacts to `MvpAwarded` via the Background Worker; not in this spec
- **The scheduler that auto-closes voting at `deadline_at`** — a `Quadra.Workers.Background` scheduled job invokes `CloseMvpVotingHandler`; the scheduling mechanism itself is out of scope here (same pattern as the F1.2 window handlers)
- **Match summary aggregation (final score + MVP + composition)** — F1.6
- **Real-time broadcast of live vote tallies** — not required by SCOPE; tallies are hidden while `Open` and revealed only after `Closed`
- **Voting by non-participants or spectators** — only match team members (F1.3) may vote or be voted for

## Implementation notes
- **`mvp_votings` + `mvp_votes` split**: these two tables jointly realize the InGame `mvp_votes` responsibility declared in ARCHITECTURE. The session/aggregate table (`mvp_votings`) is required to hold the Organizer-set deadline, the `Open | Closed` state, and the decided MVP; the per-voter table (`mvp_votes`) holds the individual ballots. This mirrors the F1.4 `scores → scoreboards + scoreboard_sets` split.
- **`MvpAwarded` realizes the ARCHITECTURE-declared InGame event** of the same name and is the single trigger for the downstream Gamification/Profile/Notifications chain. It is published only when an MVP is actually decided (≥ 1 vote).
- **Participant set**: eligible voters and candidates are exactly the `team_members` of the match (from F1.3), read via the InGame-owned `ITeamRepository`. The module never reads `match_presences` or `users` directly.
- **Vote replacement while Open**: a participant may re-submit `POST /votes` while voting is `Open`; this replaces their existing ballot (`voted_player_id` updated) without changing `total_votes`. This keeps "one name per player" while remaining user-friendly. It is not a vote-history feature — only the latest ballot is retained.
- **Self-vote enforcement**: primary check in `CastMvpVoteHandler` (returns `409`); the `CHECK (voter_player_id <> voted_player_id)` constraint is a last-resort DB guard.
- **Deterministic MVP selection**: `MvpSelectionRules.SelectWinner` is a pure, side-effect-free function, unit-tested in isolation. Highest vote count wins; ties are broken by lowest `PlayerId` (`Guid` comparison) for reproducibility in tests.
- **Deadline enforcement + auto-close**: the `deadline_at` gate is checked synchronously in `CastMvpVoteHandler` as defense in depth. The authoritative close at the deadline is performed by a `Quadra.Workers.Background` scheduled job that queries `mvp_votings WHERE state = 'Open' AND deadline_at <= now()` (backed by the `(state, deadline_at)` index) and invokes `CloseMvpVotingHandler`; that handler is organizer-agnostic when driven by the worker (the `403` organizer gate applies only to the HTTP path).
- **Event after commit**: `MvpAwarded` is published only after `SaveChangesAsync` succeeds.
- **Concurrency**: `UNIQUE (match_id, voter_player_id)` on `mvp_votes` and `UNIQUE (match_id)` on `mvp_votings` are last-resort guards; handle `DbUpdateException` on duplicate voting-open and duplicate-vote insert and return `409`.
- **Module boundary**: `Quadra.Modules.InGame` holds no `ProjectReference` to `Quadra.Modules.Matches`, `Quadra.Modules.Gamification`, `Quadra.Modules.Profile` or `Quadra.Modules.Notifications`. It depends only on `IMatchReader` (`Quadra.Shared.Contracts`), resolved via DI, plus its own `ITeamRepository` and `IScoreboardRepository`.
- **`TimeProvider` injection**: reuse the singleton registered in F1.3's `InGameModuleExtensions`; use `TimeProvider.GetUtcNow()` for all `now` timestamps and deadline defaulting.
- **CancellationToken**: propagated through every async handler, repository and interface call.
- **Serilog**: log `MatchId`, `DeadlineAt` on open; log `MatchId`, `VoterPlayerId`, `VotedPlayerId` at `Debug` on each cast vote (never above `Debug` — voter privacy); log `MatchId`, `MvpPlayerId`, `MvpVoteCount`, `TotalVotes` at `Information` on close.
- **Configuration fail-fast**: `Aws:Sqs:MvpAwardedQueueUrl` is validated at startup in `InGameModuleExtensions`; missing config throws `InvalidOperationException`.
